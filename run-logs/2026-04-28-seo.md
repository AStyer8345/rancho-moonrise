### AggregateRating extended to 5 high-commercial-intent BlogPosting landing pages

**Pages edited (5):**
1. `pages/wedding-venues-near-austin.html`
2. `pages/corporate-retreat-near-austin.html`
3. `pages/ranch-wedding-texas.html`
4. `pages/bachelorette-party-austin-texas.html`
5. `pages/pool-day-pass-austin.html`

**Schema-design choice — publisher, not article.** All 5 pages use `BlogPosting` as their primary schema. Putting `aggregateRating` on a BlogPosting risks Google interpreting it as the article's rating rather than the venue's. Embedded `aggregateRating` (4.9 / 125 / bestRating 5) inside the existing `publisher.Organization` block instead — this attaches the rating to "Rancho Moonrise" (the publisher entity), which is what we want surfaced.

**Pattern applied (uniform across all 5 pages):**
```json
"publisher": {
    "@type": "Organization",
    "name": "Rancho Moonrise",
    "url": "https://ranchomoonrise.com",
    "aggregateRating": {
        "@type": "AggregateRating",
        "ratingValue": "4.9",
        "reviewCount": "125",
        "bestRating": "5"
    }
}
```

**Anchor count held at 125.** review-monitor RUN_012 confirmed the WebSearch snippet at 175 is now 2-run-stable, but this task does not bump the AggregateRating anchor without an authoritative source. Review-count claims belong to `rancho-review-monitor`.
