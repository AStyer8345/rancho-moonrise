## 1. Google Business Profile — RESOLVED, and the ask was an artifact of search scope

The 2026-08-19 run reported: *"Google Business Profile — no canonical URL exists anywhere in the repo, and it is the single highest-value missing entry."* That statement was **true and correctly scoped to what it searched**. It then became a NEEDS ADAM ask, and that step was the error.

The IDs were one directory over, in `memory/reference_rancho_gbp.md`, captured from Adam's own `business.google.com` session:

```
Location number (n) : 224637916968489099
Feature ID (fid)    : 10788924849497903065
```

The `fid` **is** the CID. The canonical public GBP address is `https://www.google.com/maps?cid=<CID>`.

**Live verification (two independent factors):**

1. **Provenance** — the fid came from the GBP Manager URL for this location, i.e. from inside Adam's own profile.
2. **Live fetch** — `curl` with a Googlebot UA against `https://www.google.com/maps?cid=10788924849497903065` returns:
   ```
   <title>Rancho Moonrise - Google Maps</title>
   <link href="https://maps.google.com/" rel="canonical">
   ```

Note the fetch mechanics, because they cost a round trip: Google Maps serves a JS shell to `WebFetch` and to a default `curl` UA — **both look like "no such business."** Only the Googlebot UA renders the server-side `<title>`. A default-UA read here produces a confident false negative.

> **Pattern, third instance on this property.** An observed absence is a property of your query. 8/19 searched the *repo*, found nothing, and converted "not in the repo" into "only Adam can supply it." The prior two instances are logged in `feedback_page_to_exhaustion_before_claiming_boundary`. The check that would have caught it: *before writing a NEEDS ADAM, name the search scope out loud and ask what sits outside it.*
