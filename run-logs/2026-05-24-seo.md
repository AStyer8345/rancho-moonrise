## Why `inLanguage` and not the backup slots
- **`isAccessibleForFree: true`** (5/23 backup pick) — also valid, but `inLanguage` is the higher-leverage signal: it directly disambiguates `en-US` from `en-GB`/`en-AU` for international AI engines (Perplexity, Bing) and is the schema.org CreativeWork property AEO crawlers actually use to filter region-targeted results. `isAccessibleForFree` defends against paywall mis-classification — useful, but Rancho has no paywall risk surface.
- **Person-author schema** — still BLOCKED on NEEDS ADAM byline decision (whose name goes on posts: Adam, Ashley, "Rancho Moonrise editorial"?). Not autonomous.
- **`/corporate-retreats/` nav promotion** — needs Adam confirm; nav changes are visible-to-customer and live outside the schema slot.
- BCP 47 tag `en-US` chosen over bare `en` because Bing in particular weights regional variants more heavily for SERP geo-targeting; Google accepts either but prefers the more specific form per its developer docs.

## Method
- Pre-flight: enumerated all 17 BlogPosting pages via `grep -l '"@type": "BlogPosting"' site/pages/*.html`. Confirmed `keywords` is the last property in every BlogPosting JSON-LD block (uniform structure inherited from the 5/21 articleSection pass).
- Edit: Python regex anchored on `{ "@context"...BlogPosting...keywords": [...] }` with a single capture group on the closing `]`, replaced with `],\n        "inLanguage": "en-US"\n    }`. Uniform diff: +31 bytes per file (exactly one new property line).
- Bumped `"dateModified": "2026-05-23"` → `"dateModified": "2026-05-24"` via a count=1 regex (BlogPosting `dateModified` is the first occurrence in each file).
- Sitemap: per-slug regex match on `<loc>https://ranchomoonrise.com/blog/<slug>/</loc>` + adjacent `<lastmod>`, bumped 17 entries.
