## Shipped

**`scripts/serp-baseline.py`** — 10-keyword SERP baseline harness for `rancho-seo-s7`. Keyword list mirrors `tasks/seo-aeo/master-agent.md`. Three deliberate design choices, each one a bug I hit and fixed in this run:

1. **Parse by opening marker, not balanced tags.** Bing nests `<li>` inside result blocks, so `<li class="b_algo">.*?</li>` terminates on an inner tag. First attempt found 10 blocks and extracted 0 titles.
2. **Domain from `<cite>`, not the `<h2>` href.** That href is a bing.com tracking redirect — reading it reported `bing.com` as the domain of all 50 results, which would have reported the target absent from every SERP including its own.
3. **Brand canary runs first, and it is a hard gate.** On failure the script writes `MEASUREMENT BLOCKED` with **zero** per-keyword rows and exits 2. It is structurally incapable of emitting a false "0/10".

Also pins `mkt=en-US&cc=US` so future runs stay comparable (an unpinned query drifted to Homewood, AL).

**`tasks/seo-aeo/BLOCKERS.md`** — rewritten. Cleared the 108-day-stale DNS blocker that still gated "all SEO/AEO work"; added the SERP-measurement blocker with evidence and unblock path; added the GSC crawl gate.

**`client-ops/templates/re-verify-before-report.md`** — the shared fleet runbook named "DuckDuckGo HTML" as *the* verification path for SERP claims. That path is dead, so **every client task following the runbook has been unable to verify a SERP claim it surfaces.** Added a "Known-dead verification paths" section and made the brand canary a mandatory guard fleet-wide.
